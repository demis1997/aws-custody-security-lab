# Attacker capabilities

A host compromise grants that domain's runtime access and the ability to exercise live decrypted material. A domain administrator may replace hosts, deployment roles and key policies in its account. A coordinator controls orchestration and may retain issued signed bytes but does not automatically possess approval keys or two signing shares.

A compromised authorization service is modeled as controlling both approval keys only in the explicit shared-authority case. This can authorize a dishonest business request inside the signers' standing policy. One approval key or a changed recipient without bound approvals is rejected.

Stolen role credentials inherit their actual declared role graph; no implicit cross-account escalation edge is assumed. A shared deployment principal controlling all signer releases is modeled separately and reaches all signers. Key-policy administration can expose one share in the declared envelope model; it is not equivalent to generic MPC capability inside KMS.

Recovery operator, checkpoint publisher and trusted-latest selector are separate capabilities. Joint rollback means the attacker can replace both stored state and the independent current anchor; the counterexample intentionally permits replay. A missing checkpoint is not silently reconstructed from the backup being evaluated.

Organizations management can remove SCPs. It reaches member admins only when member trust explicitly grants that path. Provider/root compromise, hardware attacks, BGP/region failures and real CA compromise are residual risks, not executed attacks.
